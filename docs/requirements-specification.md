# Routine Market 요구사항 명세서

- 문서 버전: 1.0
- 최종 갱신일: 2026-09-14
- 기준 문서: `2224069 최재관 캡스톤프로젝트I 개인프로젝트 계획서_수정본.pdf`
- 대상 릴리스: 캡스톤 프로젝트 MVP
- 기술 기준: Django, PostgreSQL, Django Template, AWS EC2/RDS/S3

## 1. 문서 목적

이 문서는 Routine Market 웹 서비스의 MVP 범위와 동작을 명확히 정의하고, 설계·개발·테스트의 공통 기준으로 사용한다.

Routine Market은 검증된 트레이너와 코치가 제작한 운동 루틴을 디지털 상품으로 등록하고, 사용자가 운동 분야·난이도·목적·기간·가격에 따라 검색하여 가상 구매한 뒤 엑셀 파일로 내려받을 수 있는 웹 기반 마켓플레이스다.

## 2. 프로젝트 목표

1. 여러 채널에 분산된 운동 루틴과 트레이너 정보를 한 곳에서 탐색할 수 있게 한다.
2. 관리자가 확인한 트레이너만 운동 루틴을 판매하도록 권한을 통제한다.
3. 상품 탐색부터 주문, 다운로드, 리뷰까지 하나의 서비스에서 처리한다.
4. 구매자·판매자·관리자가 각자 필요한 정보와 기능에만 접근하도록 한다.

## 3. 범위

### 3.1 MVP 포함 범위

- 회원가입, 로그인, 로그아웃
- 회원 이메일·이름·닉네임 수정, 비밀번호 변경·재설정
- 일반회원·트레이너·관리자 역할과 권한 구분
- 트레이너 인증 신청, 승인 및 거절
- 트레이너 공개 프로필 조회 및 본인 정보 수정
- 운동 루틴 상품 등록, 수정, 조회 및 판매 상태 관리
- 상품 검색, 필터 및 정렬
- 찜과 장바구니
- 가상 결제와 주문 처리
- 구매자 전용 운동 루틴 파일 다운로드
- 구매 인증 리뷰와 평점
- 트레이너 판매 현황 조회
- Django Admin 기반 서비스 데이터 관리
- AWS 기반 배포

### 3.2 MVP 제외 범위

- 실제 금융 결제와 결제대행사 연동
- 환불, 취소 수수료 및 판매대금 정산
- 쿠폰, 포인트, 프로모션
- 실시간 채팅과 1:1 코칭
- AI 기반 운동 추천 및 루틴 생성
- 구독 상품과 반복 결제
- 모바일 애플리케이션
- 다국어 및 해외 통화 결제
- 별도의 맞춤형 관리자 대시보드

## 6. 핵심 사용자 흐름

### 6.1 구매자 흐름

1. 회원가입 또는 로그인한다.
2. 운동 분야, 난이도, 운동 목적, 기간 또는 가격으로 상품을 찾는다.
3. 상품 상세에서 트레이너 정보, 프로그램 요약, 리뷰와 평점을 확인한다.
4. 상품을 장바구니에 담고 주문을 생성한다.
5. 가상 결제를 완료한다.
6. 구매 내역에서 운동 루틴 파일을 내려받는다.
7. 구매한 상품에 평점과 리뷰를 작성한다.

### 6.2 트레이너 흐름

1. 트레이너 유형으로 가입하고 전문 분야, 경력, 자격 및 활동 정보를 제출한다.
2. 관리자의 심사 결과를 확인한다.
3. 승인된 뒤 운동 루틴 상품과 파일을 등록한다.
4. 상품을 공개하고 판매 상태를 관리한다.
5. 상품별 판매 건수, 평균 평점과 가상 매출을 확인한다.

### 6.3 관리자 흐름

1. 인증 신청자의 제출 정보와 증빙자료를 확인한다.
2. 신청을 승인하거나 거절하고 필요한 경우 사유를 기록한다.
3. 회원, 상품, 카테고리, 주문과 리뷰를 조회·관리한다.
4. 부적절한 상품 또는 리뷰를 비공개 처리한다.

| FR-AUTH-005 | 트레이너도 일반회원과 동일하게 다른 판매자의 상품을 구매할 수 있어야 한다. | 필수 | 승인 트레이너 계정으로 검색, 주문, 다운로드와 리뷰가 가능하다. |

| FR-AUTH-008 | 사용자는 이메일로 비밀번호 재설정 링크를 받아 새 비밀번호를 설정할 수 있어야 한다. | 필수 | 등록 이메일의 유효한 일회성 링크로만 재설정된다. |
| FR-AUTH-009 | 회원가입 이메일은 제한시간 내 인증번호 확인을 완료해야 한다. | 필수 | 서버 세션에서 인증된 주소와 가입 주소가 일치할 때만 가입된다. |

| FR-TRN-004 | 거절 시 관리자는 사유를 기록할 수 있어야 한다. | 권장 | 신청자가 자신의 상태와 거절 사유를 확인할 수 있다. |

| FR-TRN-007 | 인증 트레이너의 공개 프로필에는 전문 분야, 경력, 소개, 활동 링크와 판매 요약을 표시해야 한다. | 필수 | 공개 프로필에서 민감한 자격 증빙 없이 판매 루틴과 누적 판매 건수를 확인할 수 있다. |
| FR-TRN-008 | 인증 트레이너는 본인의 공개 프로필 정보를 수정할 수 있어야 한다. | 필수 | 본인만 전문 분야, 경력, 소개와 활동 URL을 변경할 수 있고 일반회원의 직접 접근은 차단된다. |

### 7.3 상품 관리

| ID | 요구사항 | 우선순위 | 검수 기준 |
|---|---|---|---|
| FR-PRD-001 | 승인된 트레이너는 운동 루틴 상품을 등록할 수 있어야 한다. | 필수 | 필수값과 유효한 파일 제출 시 상품이 생성된다. |
| FR-PRD-002 | 상품은 제목, 가격, 카테고리, 난이도, 운동 목적, 프로그램 기간, 주당 운동 횟수, 설명, 썸네일과 원본 파일을 포함해야 한다. | 필수 | 필수 항목이 누락되면 저장되지 않고 항목별 오류가 표시된다. |
| FR-PRD-003 | 상품 상태는 `DRAFT`, `PUBLISHED`, `SUSPENDED` 중 하나여야 한다. | 필수 | 공개 목록에는 `PUBLISHED` 상품만 나타난다. |
| FR-PRD-004 | 판매자는 자신이 등록한 상품만 수정하거나 판매 중지할 수 있어야 한다. | 필수 | 다른 판매자의 상품 변경 요청이 차단된다. |
| FR-PRD-005 | 카테고리는 관리자가 추가·수정할 수 있는 데이터로 관리해야 한다. | 필수 | 코드 변경 없이 새 카테고리를 추가해 검색 조건에 표시할 수 있다. |
| FR-PRD-006 | 상품 가격은 0 이상의 정수 금액으로 저장해야 한다. | 필수 | 음수 및 정수가 아닌 입력은 거부된다. |
| FR-PRD-007 | 공개 상품 상세에는 원본 운동 루틴 파일의 직접 주소가 노출되지 않아야 한다. | 필수 | 페이지 소스와 네트워크 응답에 원본 S3 주소가 포함되지 않는다. |

## 8. 파일 요구사항

아래 수치는 MVP 초안 기준이며 실제 샘플 파일을 확인한 뒤 조정한다.

| 파일 | 허용 형식 | 최대 크기 | 공개 여부 |
|---|---|---:|---|
| 운동 루틴 | `.xlsx` | 20MB | 구매자만 다운로드 |
| 상품 썸네일 | `.jpg`, `.jpeg`, `.png`, `.webp` | 5MB | 공개 |
| 자격 증빙 | `.jpg`, `.jpeg`, `.png`, `.pdf` | 10MB | 신청자와 관리자만 접근 |

- 파일 확장자와 MIME 유형을 함께 검사한다.
- 실행 파일, 매크로 포함 엑셀 형식과 허용되지 않은 파일은 거부한다.
- 저장 파일명은 서버에서 안전한 고유값으로 변환하고 사용자가 입력한 경로를 신뢰하지 않는다.
- 동일 상품의 파일을 교체하더라도 기존 구매자는 주문 당시 연결된 파일 버전을 받는다.

## 9. 데이터 요구사항과 무결성

### 9.1 주요 엔티티

- `User`: 로그인 정보, 기본 프로필, 역할
- `TrainerProfile`: 전문 분야, 경력, 자기소개, 공개 활동 정보
- `TrainerApplication`: 신청 상태, 신청·처리시각, 거절 사유
- `Certification`: 자격명, 발급기관, 증빙파일
- `Category`: 운동 분야 분류
- `ExerciseGoal`: 체력 증진, 체중 관리 등 운동 목적
- `Product`: 상품 정보, 판매자, 공개 상태
- `ProductFile`: S3 객체 키, 원본 파일명, 버전 정보
- `Wishlist`: 사용자와 상품의 찜 관계
- `Cart`, `CartItem`: 사용자의 현재 장바구니
- `Order`, `OrderItem`: 주문과 상품·가격 스냅샷
- `Review`: 구매자, 상품, 평점, 내용
- `DownloadLog`: 구매 파일 접근 기록

### 9.2 필수 제약조건

- 사용자 이메일은 중복될 수 없다.
- 사용자와 상품 조합의 찜은 하나만 존재한다.
- 장바구니 안에서 같은 상품은 하나만 존재한다.
- 사용자와 상품 조합의 리뷰는 하나만 존재한다.
- 상품 가격과 주문 금액은 음수일 수 없다.
- 주문 합계는 주문 항목 금액의 합과 일치해야 한다.
- 삭제된 사용자나 상품으로 인해 과거 주문의 상품명과 금액 기록이 유실되지 않아야 한다.
- 트레이너 본인이 자신의 상품을 구매하는 행위는 차단한다.

## 10. 상태 전이

### 10.1 트레이너 인증

```text
PENDING -> APPROVED
PENDING -> REJECTED
REJECTED -> PENDING  (정보를 수정하여 재신청할 때)
```

승인 취소 기능은 MVP 필수 범위에서 제외한다. 운영상 필요하면 관리자가 사용자와 상품을 비활성화한다.

### 10.2 상품

```text
DRAFT -> PUBLISHED
PUBLISHED -> SUSPENDED
SUSPENDED -> PUBLISHED
```

미승인 트레이너의 상품은 `PUBLISHED` 상태로 전환할 수 없다.

### 10.3 주문

```text
PENDING -> PAID
PENDING -> CANCELLED
```

MVP에서는 실제 환불을 다루지 않으므로 `PAID` 주문을 다시 취소하는 흐름은 제공하지 않는다.

### 11.1 보안

| NFR-SEC-005 | S3 버킷의 퍼블릭 액세스를 차단하고 서버가 승인한 경우에만 제한된 URL을 발급한다. |

### 11.2 성능

- 상품 1,000건, 동시 사용자 20명 규모의 캡스톤 시연 환경을 기준으로 한다.
- 일반적인 목록·상세 요청은 테스트 환경에서 95%가 2초 이내 응답하는 것을 목표로 한다.
- 상품 목록은 페이지네이션을 적용하며 한 페이지에 12~24개를 표시한다.
- 검색 조건에 사용되는 상태, 카테고리, 난이도, 목적, 가격에는 필요한 데이터베이스 인덱스를 적용한다.
- 큰 파일은 Django가 직접 전송하지 않고 S3 서명 URL로 전달한다.

### 11.3 신뢰성과 데이터 일관성

- 결제 완료, 주문 항목 생성과 판매 통계 반영은 원자적으로 처리한다.
- 동일 요청 재처리로 주문 또는 판매 집계가 중복되지 않아야 한다.
- 예외 발생 시 사용자에게 내부 오류 정보나 비밀값을 노출하지 않는다.
- 운영 데이터베이스는 정기 백업이 가능한 설정을 사용한다.

### 11.4 사용성 및 호환성

- 데스크톱과 모바일 화면에서 핵심 기능을 사용할 수 있는 반응형 화면을 제공한다.
- 폼 오류는 해당 입력 항목 가까이에 이해하기 쉬운 한국어로 표시한다.
- 키보드로 핵심 폼과 버튼을 조작할 수 있어야 한다.
- 이미지에는 대체 텍스트를 제공하고 폼 입력에는 명시적인 레이블을 사용한다.
- 최신 Chrome과 Edge 브라우저에서 기능을 검증한다.

### 11.5 운영과 관찰 가능성

- 로그인 실패, 서버 오류, 관리자 승인·거절과 다운로드 요청을 필요한 범위에서 기록한다.
- 로그에는 비밀번호, 세션 값, AWS 키와 자격 증빙 원본 내용을 남기지 않는다.
- 사용자에게 표시되는 오류와 운영 로그의 상세 오류를 분리한다.

## 13. MVP 인수 테스트 시나리오

### AT-001 트레이너 승인과 판매

1. 트레이너 신청자가 자격과 경력 정보를 제출한다.
2. 승인 전에는 상품 등록 요청이 거부된다.
3. 관리자가 신청을 승인한다.
4. 승인된 트레이너가 상품을 등록하고 공개한다.
5. 공개 상품이 검색 결과에 나타난다.

### AT-002 상품 탐색과 구매

1. 구매자가 복수 검색 조건을 적용한다.
2. 조건에 맞는 공개 상품만 표시된다.
3. 구매자가 상품을 장바구니에 담고 주문한다.
4. 가상 결제를 완료한다.
5. 구매 내역에 주문과 상품이 표시된다.
6. 주문 당시 가격이 보존된다.

### AT-003 구매 파일 보호

1. 비구매자가 파일 다운로드를 요청하면 거부된다.
2. 결제 대기 주문의 사용자가 요청해도 거부된다.
3. 결제 완료 구매자가 요청하면 만료시간이 있는 다운로드 URL이 발급된다.
4. 발급 URL은 만료 후 사용할 수 없다.

### AT-004 리뷰 무결성

1. 비구매자는 리뷰를 작성할 수 없다.
2. 구매자는 1~5점의 평점과 리뷰를 작성할 수 있다.
3. 같은 사용자가 같은 상품에 두 번째 리뷰를 작성하면 거부된다.
4. 리뷰 변경 후 상품 평균 평점이 정확히 갱신된다.

### AT-005 권한 분리

1. 트레이너 A는 트레이너 B의 상품을 수정할 수 없다.
2. 사용자는 다른 사용자의 주문과 구매 내역을 볼 수 없다.
3. 일반 사용자는 트레이너 증빙자료를 볼 수 없다.
4. 관리자만 트레이너 승인 상태를 변경할 수 있다.

## 14. 확정된 MVP 설계와 후속 정책

다음 1~5, 7 항목은 현재 구현에 반영된 기준이다. 6과 8은 운영 정책 또는 고도화 단계에서 최종 확정한다.

1. 모든 사용자는 기본 회원 계정을 만든 뒤 트레이너 인증을 신청한다.
2. 한 주문에 여러 판매자의 상품을 담을 수 있다.
3. 이미 결제 완료한 디지털 상품의 재구매는 차단한다.
4. 상품 파일 버전을 보존하고 기존 구매자는 주문 당시 버전을 받는다.
5. 가격 0원 상품을 허용한다.
6. 계정 비활성화 후 거래 기록을 보존하는 방향이며, 보유기간과 요청 절차는 공개 전 확정한다.
7. 판매량과 가상 매출은 별도 누적 필드 없이 결제 완료 주문에서 계산한다.
8. 인기 상품의 기간·가중치 기준은 고도화 단계에서 확정한다.

## 15. 완료 정의

MVP는 다음 조건을 모두 만족해야 완료된 것으로 판단한다.

- 13장의 인수 테스트 시나리오가 모두 통과한다.
- 필수 우선순위 기능 요구사항을 자동 또는 수동 테스트로 검증한다.
- 권한 없는 상품 수정, 주문 조회, 파일 다운로드와 리뷰 작성이 차단된다.
- 운영 환경에서 PostgreSQL과 비공개 S3 저장소를 사용한다.
- 샘플 트레이너, 상품, 주문과 리뷰 데이터로 전체 시연이 가능하다.
- README에 로컬 실행, 환경변수, 데이터베이스 마이그레이션과 배포 방법이 기록되어 있다.
- 저장소에 비밀번호, Secret Key 또는 AWS 접근키가 포함되지 않는다.

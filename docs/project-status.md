# Routine Market 개발 현황 및 향후 작업

- 작성일: 2026-09-11
- 현재 단계: AWS 운영 배포 완료, HTTPS 및 운영 안정화 전
- 기술 구성: Python 3.14, Django 5.2 LTS, PostgreSQL 대상 설계, Django Template
- 자동 테스트: 로컬 PostgreSQL 기반 27개 통과

## 1. 현재 진행 상태 요약

현재 `회원가입 → 트레이너 인증 신청 및 승인 → 상품 등록 → 상품 검색 → 찜 및 장바구니 → 주문 → 가상 결제 → 구매 파일 다운로드 → 리뷰 작성`으로 이어지는 MVP 핵심 흐름이 코드로 연결되어 있다.

로컬 개발 환경은 PostgreSQL 16과 서울 리전의 실제 비공개 S3 저장소를 사용하며, 기존 SQLite와 로컬 파일 저장소로도 전환할 수 있다. 운영 환경은 서울 리전 EC2, 비공개 RDS PostgreSQL 16.13과 비공개 S3를 사용한다. Gunicorn·Nginx 서비스, RDS 마이그레이션, 데모 데이터, 실제 로그인·구매 내역과 S3 이미지 응답까지 검증했다.

## 5. 현재 알려진 제한사항

- 운영 주소는 고정 IP의 HTTP이며 도메인과 HTTPS는 아직 적용하지 않았다.
- RDS는 비용을 낮춘 Single-AZ 구성이라 가용영역 장애 자동 전환을 제공하지 않는다.
- 로컬 S3 사용 전 `routine-market` SSO 프로필 로그인이 필요하며 SSO 세션은 만료될 수 있다.
- 로컬 파일 저장 중 데이터베이스 트랜잭션이 실패하면 저장소에 고아 파일이 남을 수 있다.
- 비밀번호 재설정, 이메일 인증과 이메일 알림은 구현되어 있지 않다.
- 상품 썸네일 또는 루틴 파일 교체 시 사용하지 않는 과거 파일을 정리하는 운영 정책이 없다.
- 실제 결제, 환불 및 판매자 정산은 요구사항에 따라 MVP 범위에서 제외했다.
- 핵심 화면의 모바일 Chromium 검수는 완료했지만 Edge, 실제 기기와 접근성 검수는 남아 있다.
- 서비스 이용약관, 개인정보 처리방침과 운동 프로그램 면책 고지가 아직 없다.

- Django 데이터베이스를 SQLite에서 로컬 PostgreSQL로 전환
- 전체 Django 마이그레이션 적용 및 기본 카테고리 6개 생성 확인
- `python-dotenv`를 적용해 Git에서 제외되는 `.env`로 로컬 설정 관리
- Django 시스템 검사와 PostgreSQL 연결 확인 완료
- `routine_market_user`에 테스트 데이터베이스 생성 권한 부여
- PostgreSQL `test_routine_market` 데이터베이스에서 전체 자동 테스트 27개 통과

### 7.3 시연 환경 검증

- `pgpass.conf`의 데이터베이스 패턴을 조정해 운영·테스트 DB 모두 비밀번호 비노출 접속 확인
- `seed_demo` 반복 실행과 `--reset` 후 표준 시연 데이터 복원 확인
- 모바일 390×844 뷰포트에서 홈·상품 상세·장바구니·구매 내역 가로 넘침 없음 확인
- S3에 저장된 데모 썸네일 3개의 브라우저 로딩과 1200×675 원본 크기 확인

### 7.4 AWS 운영 배포

- 서울 리전 기본 VPC와 4개 기본 서브넷 확인
- Ubuntu 24.04 LTS 최신 AMI 확인
- 운영용 Gunicorn, Nginx와 systemd 구성 작성
- RDS SSL 모드, CSRF 신뢰 출처, 프록시 보안 헤더와 운영 로그 설정 추가
- `/health/` 엔드포인트 및 자동 테스트 추가
- `t3.micro` EC2, 암호화 gp3 12GB와 고정 Elastic IP 구성
- 비공개 Single-AZ RDS PostgreSQL 16.13 `db.t4g.micro`, 암호화 gp3 20GB 구성
- 웹·DB 보안 그룹을 분리하고 DB 5432 포트를 EC2 보안 그룹에만 허용
- EC2 인스턴스 역할, SSM 접속과 S3 버킷 경로 제한 정책 구성
- RDS 관리자·애플리케이션 계정을 분리하고 Secrets Manager로 비밀번호 관리
- 운영 환경 파일 권한 600, 장기 AWS 키 미사용 확인
- 전체 마이그레이션과 데모 데이터 적용
- 외부 상태 확인, 홈페이지, 로그인, 구매 내역과 S3 썸네일 HTTP 200 검증

보안상 AWS 액세스 키, SSO 토큰, 데이터베이스 비밀번호와 로컬 `.env` 파일은 Git에 포함하지 않는다.

## 8. 권장 진행 순서

1. AWS 예산·크레딧 알림을 설정하고 리소스 운영 기간을 결정한다.
2. 도메인과 HTTPS를 적용하고 보안 쿠키·HSTS를 활성화한다.
3. 로그인 방어, 파일 정리와 백업 정책 등 운영 보안을 보완한다.
4. 비밀번호 재설정과 회원·트레이너 프로필 등 사용자 기능을 확장한다.
5. Edge·실제 모바일·접근성 및 동시 요청 테스트를 확대한다.
6. 최종 보고서, 화면 캡처와 발표 자료를 완성한다.

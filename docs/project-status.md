# Routine Market 개발 현황 및 향후 작업

- 작성일: 2026-09-08
- 현재 단계: MVP 핵심 사용자 흐름 구현 완료, 배포 및 안정화 전
- 기술 구성: Python 3.14, Django 5.2 LTS, PostgreSQL 대상 설계, Django Template
- 자동 테스트: 19개 통과

## 1. 현재 진행 상태 요약

현재 `회원가입 → 트레이너 인증 신청 및 승인 → 상품 등록 → 상품 검색 → 찜 및 장바구니 → 주문 → 가상 결제 → 구매 파일 다운로드 → 리뷰 작성`으로 이어지는 MVP 핵심 흐름이 코드로 연결되어 있다.

로컬 개발 환경에서는 SQLite와 로컬 파일 저장소를 사용한다. PostgreSQL 환경변수 설정, 비공개 파일 전달 인터페이스와 AWS 배포 구조는 준비되어 있지만 실제 RDS·S3·EC2 연결과 운영 배포는 아직 진행하지 않았다.

## 5. 현재 알려진 제한사항

- 운영용 PostgreSQL과 AWS 서비스가 실제로 연결되어 있지 않다.
- S3 전환용 다운로드 분기는 존재하지만 `django-storages`, S3 버킷과 IAM 설정은 아직 없다.
- 로컬 파일 저장 중 데이터베이스 트랜잭션이 실패하면 저장소에 고아 파일이 남을 수 있다.
- 트레이너 거절 서비스는 구현되어 있으나 Django Admin의 전용 거절 액션과 거절 사유 입력 흐름은 보완이 필요하다.
- 비밀번호 재설정, 이메일 인증과 이메일 알림은 구현되어 있지 않다.
- 상품 썸네일 또는 루틴 파일 교체 시 사용하지 않는 과거 파일을 정리하는 운영 정책이 없다.
- 실제 결제, 환불 및 판매자 정산은 요구사항에 따라 MVP 범위에서 제외했다.
- UI 자동화 테스트와 실제 브라우저별·모바일 기기별 검수는 아직 수행하지 않았다.
- 사용자용 404·403·500 오류 화면이 아직 없다.
- 서비스 이용약관, 개인정보 처리방침과 운동 프로그램 면책 고지가 아직 없다.

## 6. 앞으로 남은 작업

### 6.1 우선순위 P0: MVP 시연 안정화

- 전체 흐름을 재현할 수 있는 데모 데이터 생성 명령 작성
- 구매자, 승인 대기 트레이너, 승인 트레이너와 관리자 데모 계정 준비
- 샘플 썸네일과 실제 XLSX 운동 루틴 파일 준비
- 관리자 트레이너 거절 액션 및 처리 이력 보완
- 403·404·500 오류 화면 작성
- 주요 폼과 모바일 반응형 화면 수동 검수
- 발표용 전체 시연 시나리오와 체크리스트 작성

완료 기준:

- 초기 데이터가 없는 환경에서 명령 한 번으로 데모 데이터를 구성할 수 있다.
- 구매자와 트레이너의 핵심 흐름을 중단 없이 시연할 수 있다.
- 권한 오류와 잘못된 파일 입력이 사용자 친화적인 화면으로 처리된다.

### 6.2 우선순위 P0: PostgreSQL 및 AWS 연결

- 로컬 PostgreSQL 실행 환경 구성
- PostgreSQL에서 전체 마이그레이션과 테스트 실행
- AWS RDS for PostgreSQL 생성 및 보안 그룹 설정
- 비공개 S3 버킷과 상품 썸네일 저장 정책 구성
- `django-storages`와 `boto3` 적용
- 운동 루틴과 자격 증빙에 만료되는 서명 URL 적용
- EC2, Gunicorn과 Nginx 배포 구성
- 도메인 또는 임시 배포 주소와 HTTPS 적용
- 운영 환경변수와 비밀정보 관리

완료 기준:

- 운영 서버가 RDS와 S3를 사용한다.
- 비구매자는 S3 객체 주소를 알아도 운동 루틴을 받을 수 없다.
- 저장소와 서버에 AWS 키, 데이터베이스 비밀번호와 Django Secret Key가 노출되지 않는다.

## 7. 권장 진행 순서

1. 데모 데이터와 관리자 거절 흐름을 완성한다.
2. PostgreSQL에서 마이그레이션과 테스트를 검증한다.
3. S3 비공개 파일 저장과 서명 URL을 연결한다.
4. EC2·RDS·Nginx·Gunicorn 운영 환경에 배포한다.
5. 브라우저 기반 전체 시나리오 테스트를 수행한다.
6. 오류 화면, 보안 설정과 문서를 보완한다.
7. 발표 시나리오와 최종 산출물을 작성한다.
